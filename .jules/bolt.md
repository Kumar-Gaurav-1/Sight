## 2024-05-18 - Globally cached DateFormatter avoids duplicate initialization in Sight
**Learning:** Frequent instantiations of `DateFormatter` and `ISO8601DateFormatter` in loops, chart renderings, telemetry payloads, and stats generation are exceptionally expensive. This causes unneeded memory allocations and CPU overhead in Sight. Swift strict concurrency checks require such shared formatters to be marked `Sendable` (via `final class` wrapping or explicit `@unchecked Sendable`) and using `#if compiler(>=5.10)` correctly handles older CI compiler environments without syntax errors.
**Action:** When creating shared DateFormatters across the codebase, always use a single cached `public static` instance in a utility struct/class to replace localized initializations, taking care to respect strict concurrency bounds.
