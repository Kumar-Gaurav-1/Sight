## 2024-10-14 - CI Failure due to strict concurrency and legacy Swift syntax
**Learning:** After extracting `DateFormatter` instantiations, the CI pipeline running older Swift versions failed due to unrelated strict concurrency warnings being treated as errors and unsupported syntax. Specifically, `nonisolated(unsafe)` is invalid in Swift < 5.10, generating an `expected 'var' keyword` syntax error. Furthermore, accessing `@MainActor` isolated static properties (like `SightTheme.accent`) inside non-isolated `View` structs triggers errors. Capturing `[weak self]` outside of a `Task { @MainActor in }` and unwrapping it inside also causes a compiler error.
**Action:** 1) For Swift < 5.10 compatibility, wrap `nonisolated(unsafe) public static var shared` with `#if compiler(>=5.10)` and fallback to standard `public static var`. 2) Annotate non-isolated SwiftUI `View` structs (like `ActivityHeatmapView`, `SightAboutView`, etc.) with `@MainActor` when they access isolated theme state. 3) For `Task` execution inside a closure, unwrap `self` safely outside the `Task` and explicitly capture the unwrapped strong reference in the `Task { @MainActor [self] in }` capture list to avoid concurrency capturing errors.
## 2024-10-14 - CI Failure due to macOS version constraint on `assumeIsolated`
**Learning:** `MainActor.assumeIsolated` requires macOS 14.0 or newer. Using it causes compilation failures on build targets supporting older macOS versions. When a globally accessed static UI property (like a theme color) needs to read state stored in an `@MainActor` class (like a `PreferencesManager` reading `UserDefaults`), doing so synchronously without actor isolation triggers strict concurrency warnings, but `assumeIsolated` breaks older platform support.
**Action:** Bypassed the `@MainActor` state manager completely in the static property by reading the underlying source directly (e.g., `UserDefaults.standard.double(forKey:)`) and applying the known default value if missing. This guarantees synchronous, thread-safe access without requiring `@MainActor` annotations or `assumeIsolated`.
