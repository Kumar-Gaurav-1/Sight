## 2024-10-14 - Expensive DateFormatter Initialization in Loops and Views
**Learning:** Found widespread instantiations of `DateFormatter` and `ISO8601DateFormatter` in loops, chart rendering functions, and property accessors across multiple files. Because creating a `DateFormatter` is computationally expensive in Swift, allocating these locally inside frequent operations (e.g., rendering charts, processing export loops, or formatting menu bar updates) can cause substantial performance regressions and UI hitching on macOS. In Swift, these should be shared globally if thread-safe, or instantiated once per context.
**Action:** Created a `SharedFormatters: @unchecked Sendable` globally accessible singleton with lazy-initialized, thread-safe formatters, and refactored local instances across `InteractiveCharts`, `AdherenceManager`, `StatisticsEngine`, and others to use this global cache. Ensure to use `@unchecked Sendable` because `DateFormatter` properties (though thread-safe if unmutated after setup) are not implicitly `Sendable` by the compiler.
