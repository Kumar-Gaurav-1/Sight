## 2024-10-25 - DateFormatter Performance Cache Optimization
**Learning:** Initial attempt to use `lazy var` for properties on an `@unchecked Sendable` singleton class introduced critical thread-safety vulnerabilities. `lazy var` is inherently not thread-safe in Swift and bypassing concurrency checks hides these potential data races. Furthermore, hardcoding a generic string format to replace `DateFormatter` configurations (e.g., overriding `.timeStyle = .short` with `"h:mm a"`) creates severe localization regressions.
**Action:** Re-implemented the `SharedFormatters` cache. Instead of `lazy var`, instantiated all formatters synchronously inside the singleton's private `init()` and assigned them to constant `let` properties, guaranteeing thread-safe initialization. Created a specific `.shortTime` formatter to properly preserve user 12/24h localization settings, and fixed the day string layout regression by including a proper `"EEE"` formatter instead of incorrectly re-using `"EEEE"`.
