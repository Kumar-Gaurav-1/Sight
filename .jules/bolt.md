## 2024-10-25 - DateFormatter Performance Cache Optimization
**Learning:** Initial attempt to use `lazy var` for properties on an `@unchecked Sendable` singleton class introduced critical thread-safety vulnerabilities. `lazy var` is inherently not thread-safe in Swift and bypassing concurrency checks hides these potential data races. Furthermore, hardcoding a generic string format to replace `DateFormatter` configurations (e.g., overriding `.timeStyle = .short` with `"h:mm a"`) creates severe localization regressions.
**Action:** Re-implemented the `SharedFormatters` cache. Instead of `lazy var`, instantiated all formatters synchronously inside the singleton's private `init()` and assigned them to constant `let` properties, guaranteeing thread-safe initialization. Created a specific `.shortTime` formatter to properly preserve user 12/24h localization settings, and fixed the day string layout regression by including a proper `"EEE"` formatter instead of incorrectly re-using `"EEEE"`.

## 2024-10-25 - Strict Concurrency Isolation Fixes
**Learning:** Found CI failing due to cascading actor isolation errors. A singleton `TimerStateMachine` was declared as `nonisolated(unsafe) public static var shared: TimerStateMachine!` but failed to compile on older Swift versions (missing var keyword errors). Furthermore, replacing closures that capture `[weak self]` with `[self]` inside `Task { @MainActor in }` must be done carefully by unwrapping `self` synchronously *outside* the Task, and then strongly capturing the unwrapped reference in the Task's capture list, otherwise it leaks or fails compilation. Lastly, when global UI constants (like `SightTheme.accent`) read from `@MainActor`-isolated state (like `PreferencesManager`), those constants MUST be `@MainActor`, and consequently, any non-isolated view structs or private helper methods (like `intensityColor`) referencing them must explicitly add `@MainActor`. Additionally, `Foundation.Notification` does not conform to the `Sendable` protocol. Capturing it in a `@Sendable` closure (e.g., `NotificationCenter.default.addObserver` paired with an internal `Task`) causes strict concurrency compiler errors. Non-sendable types must be processed synchronously outside the Task, passing only the extracted, sendable values into the concurrent context.
**Action:** Wrapped `nonisolated(unsafe)` in `#if compiler(>=5.10)` blocks to preserve backward compatibility. Extracted `guard let self = self else { return }` outside of `Task` closures and used `Task { @MainActor [self] in }` for correct concurrency bridging. Added explicit `@MainActor` annotations to SwiftUI view structs and helper methods that read from main-actor isolated theme colors.
