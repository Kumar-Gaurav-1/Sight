
## 2023-10-27 - DateFormatter Optimization and Swift Concurrency Traps
**Learning:** In Swift 6 strict concurrency, modifying `ButtonStyle` and `ToggleStyle` directly with `@MainActor` causes compilation failures because their `makeBody` requirement is nonisolated. Attempting to fix `reference to captured var 'self' in concurrently-executing code` errors by indiscriminately changing Combine and Timer closure captures from `[weak self]` to `[self]` introduces massive retain cycles and memory leaks.
**Action:** When migrating UI styles to MainActor isolation, always extract the body logic into a separate, internal `@MainActor struct MyStyleBody: View` rather than annotating the style protocol implementation. When fixing Task closures that cross isolation domains inside `[weak self]` capture blocks, safely unwrap `self` in the outer scope (`guard let self = self else { return }`) and strictly capture the unwrapped reference in the inner Task (`Task { @MainActor [self] in }`).

## 2023-10-27 - Compiler Warnings as Errors and Sendable Notifications
**Learning:** In CI environments that treat compiler warnings as errors, assigning `var config = configuration` only to call `config.isOn.toggle()` inside a SwiftUI style triggers a fatal 'variable was never mutated' error because the mutation happens on the underlying `Binding`, not the struct. Additionally, in Swift 6, `Foundation.Notification` is NOT `Sendable`. Passing a `Notification` object into a `Task` closure results in a fatal strict concurrency error.
**Action:** Always call mutating methods directly on `configuration.isOn` in SwiftUI styles. When handling `NotificationCenter` observers, extract the required primitives (e.g., `let minutes = notification.userInfo?["minutes"] as? Int`) synchronously outside the `Task`, and pass only those sendable primitive values into the asynchronous context.
