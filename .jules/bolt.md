## 2024-06-25 - DateFormatter Performance Impact in Loops
**Learning:** Found widespread performance bottlenecks where `DateFormatter` and `ISO8601DateFormatter` were being instantiated inside frequently called methods, tight loops (e.g., CSV exports spanning hundreds of days), and SwiftUI render bodies. In Swift, these Foundation formatter initializations are notoriously computationally expensive and cause significant main-thread overhead or spikes during data transformations.
**Action:** Always extract and cache `DateFormatter` instances in a globally shared, thread-safe utility class (like `SharedFormatters: @unchecked Sendable`). Ensure `locale` and `timeZone` are set to `.autoupdatingCurrent` (except for specific fixed formats like ISO8601) so the cached singletons automatically respond to system locale changes just as dynamic instantiations would.
